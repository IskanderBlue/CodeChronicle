{% comment %} One neighbour provision in the permalink hierarchy nav. `item`: {provision_id, title, versions:[{version, title, effective_date, last_day, never_in_force, url}]}. `last_day` is the last day the version governed, already converted from the half-open window end by the view — printing the stored end date would name the first day the text did not apply. `glyph`: the direction mark for the gutter — the pager passes an arrow back or forward, the parent group an arrow up, the children group an arrow down. All four groups render through this partial, so every row in the nav is built the same way. Layout is `.pnav-row` / `.pnav-versions` (base.html): a two-column grid, a fixed gutter for the glyph and then everything else. The ids therefore start at one indent whatever the group and whatever the id's length, and the version rows sit in column two — the alignment falls out of the grid, so nothing here adds a padding computed from the gutter and the gap. Component classes rather than arbitrary Tailwind utilities, because an arbitrary utility does not exist until a build rescans this file. The row names a provision *other* than the one being read, so the id and the title go in the link (tasks/c-lineage-anchor-text.md). A single overlapping version links the id and the title together. Several overlapping versions have no single target, so the id and the title become plain text and each version gets its own row underneath — one date per row, because a wrapping line of dates gave no way to tell where one ended and the next began. The link text is the **date**: the versions differ only by date, and that is what the reader chooses between. The nav column is narrow (`--ws-nav`), so a long title truncates on one line and keeps its full text in the hover. Do not write a width down here; `min-w-0` lets the track's own token decide. {% endcomment %}
