{% comment %} ── The search form ── ONE implementation, three call sites: the search page (templates/search.html), the landing hero, and the landing's section III row 01. It used to be three separate forms, and the two copies had already drifted — both had lost the Jurisdiction cell, so the front page advertised a different instrument from the one it hands the reader. `mode` is the only fork, and it forks BEHAVIOUR, not markup: live the search page. htmx posts the query and swaps the results area in place. `id="search-form"` is load-bearing (the relevance-floor control re-runs this same query with hx-include="#search-form"), and so is `id="query"`, which the search page's own script focuses. handoff a plain GET to the search page, which reads `?q=` and `?d=`. A visitor arrives at the tool holding their own question, so the form on the front page is the product rather than a picture of it. The field names follow the mode: live posts `query` / `date` / `province`; handoff uses `q` / `d`, the public link contract the "try this" links share. Do not change either set — both are referenced outside this file. `id_prefix` namespaces the ids, because two of these forms appear on one page (the landing hero and row 01) and a duplicate id is invalid — that was a live bug here. The search page passes no prefix and keeps the bare ids its script and its hx-include depend on. The AS-OF input needs no id at all: its label wraps it. Callers may set: mode, id_prefix, initial_query, initial_date, placeholder, meta_note. `coverage_start` / `coverage_end` arrive from the context processor, so the date bounds are the corpus bounds on every surface. NB: multi-line {# #} comments leak as literal text (the tokenizer is not re.DOTALL) — use {% comment %} for anything spanning lines. {% endcomment %}

The search runs at this date, and it OVERRIDES any year the parser reads out of the query text — so a form without it sends "…, 2003" to the corpus default date and answers with the wrong edition. It defaults to `coverage_end`, the same end date the masthead shows ("Consolidation current to"), from CorpusCurrency. `initial_date` comes from `?d=` (a "try this" link, or a shared URL) or from the caller; it must win over the corpus default or the linked query runs at the wrong date. {% endcomment %}
