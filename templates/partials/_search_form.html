{% comment %} The BUILDING modal, opened from the cell in the query bar. It sits INSIDE the form on purpose: these are the real fields, so they post with the search and the relevance-floor control (hx-include="#search-form") carries them through a re-measure. A second set of inputs elsewhere would post the same names and the winner would depend on DOM order. The size fields appear only once the reader has NAMED an occupancy the code applies a size test to, on the AS-OF date they are searching. Two consequences, both intended: a blank occupancy shows nothing, because the parser has not read the query yet and a field offered on a guess is a field asking for an answer that may change nothing; and moving the AS-OF date can make them appear or vanish, because a retirement home is sized before 1 July 2017 and unsized after it. They are `:disabled` as well as hidden, so a value the code cannot use is never posted and never reaches the address. Each field carries its seeded value in the MARKUP as well as in the Alpine state. The two agree, because both come from `initial_building` — but the auto-run submits on DOMContentLoaded and Alpine initialises on the same event, so a field that relied on x-model alone could be posted empty in the very request the seed exists for.
