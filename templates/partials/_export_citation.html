That button produced one string and never said which; a citation has more than one correct form, so choosing is part of the job and a menu is the honest control. The old string is still here, as the Reference entry, so nothing a reader relied on has gone. Expects the four parts of a version reference: code_edition, division, provision_id, version The panel is fetched on the first click, not rendered with the page: a results page draws up to a hundred cards and almost nobody cites from more than one, so the strings are built for the card that was asked about. The trigger sits on the panel itself and targets "this", so nothing here needs an id: a provision id contains dots, a dot in a CSS selector means a class, and one page can render this partial twice for the same version (the wide band and the narrow banner both include it), so no id built from the target would be both selectable and unique. ``openCite`` hands the teleported panel to ``htmx.process`` — it is not optional, and it is why the results page works at all. htmx 1.9 has no mutation observer: it walks the DOM once at DOMContentLoaded, and again over whatever it swaps in itself.
