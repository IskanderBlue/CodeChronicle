{# ══ II · Built twice — the centrepiece ════════════════════════════ #}

II · How we know it is right

We build every edition twice, two different ways, and diff them.

A reconstruction you cannot check is only an assertion. So the Code is rebuilt from the regulations — and then rebuilt a second time by a completely different method. The two results are compared provision by provision, version by version, before anything is published.

{% comment %} Regulation-parsing comes FIRST: it is the route the published corpus is actually built from, and version-comparison is the independent check on it rather than an equal sibling. "Path A / Path B" told a reader nothing about which was which. {% endcomment %}
What we publish

Regulation‑parsing

Start at the base regulation that enacts the edition, then apply what each amending regulation actually instructs — revoke this, substitute that, add these words here — in filing order. This is the corpus you search.

  1. Parse the base regulation into provisions
  2. Parse each amending regulation into directives
  3. Apply the directives in filing order
  4. Date each change from its own commencement
The independent check

Historical‑version comparison

Ontario republishes the consolidated Code every time an amendment takes effect. Read those snapshots in order and the differences between them are the amendment history — recovered without reading a single directive.

  1. Fetch every e-Laws consolidation of the edition
  2. Align them provision by provision
  3. Diff each consecutive pair
  4. Date each change from the period it appears in

And where they differ, the difference has a name.

Not every difference is an error. Ontario sometimes restyles text no regulation touched, or prints a change before the day it commences. Each of those is classified, named and reviewed by hand — never averaged into a margin of error, never quietly patched.
