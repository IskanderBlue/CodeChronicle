# 5.2 — Mobile Accordion and Grouping

## Status: implemented and browser-verified (2026-07-24)

## What

Refine accordion and grouped result behavior for mobile screens.

## Why

The desktop interaction patterns need smaller-screen tuning for touch targets,
collapsed density, and grouped-child readability.

## Changes

- Tune accordion hit areas and spacing for touch.
- Ensure grouped cards remain readable when collapsed.
- Ensure child rows do not become visually ambiguous on mobile.
- Preserve Phase 1 and Phase 2 semantics; this task is refinement, not logic
  redesign.

## Completion Conditions

- Accordion controls are comfortably tappable on mobile.
- Grouped cards remain understandable in collapsed and expanded states.
- No overlap or clipping makes child rows unreadable.

## How to Test

### Browser/manual test: `mobile_accordion_touch_targets_are_comfortable`

Expected:

- Result headers are easy to tap.
- Expanding/collapsing does not require precision clicking.

### Browser/manual test: `mobile_grouped_cards_preserve_child_readability`

Expected:

- Top-scoring child remains identifiable.
- Context children remain distinguishable from matched children.

## Depends On

- 1.2 accordion results.
- 2.2 grouped accordion cards.

## Notes

- Test this on at least one narrow mobile viewport and one mid-size tablet
  viewport before marking complete.

## Implementation Update (2026-03-08)

  switching to side-by-side alignment at larger breakpoints.

## Verification Run

- Passed: `pytest core/tests/test_templates.py` (grouped + accordion subset
  re-run 2026-07-24: 5 passed).
- Browser/manual verification completed 2026-07-24 against the live dev server
  (query "fire alarm" @ as-of 2010-06-01 → OBC 2006, which yields one grouped
  card: parent `B 3.2.4.` with 5 matched children, top match `3.2.4.5.`, plus
  4 standalone results).
  - Method note: the browser-automation harness could not shrink the OS window
    below 1920px (`resize_window` returned success but `innerWidth` stayed
    pinned; `Page.captureScreenshot` also intermittently timed out). Verified
    instead by force-showing the `lg:hidden` mobile accordion at constrained
    box widths and measuring real rendered geometry (`getBoundingClientRect`)
    plus captured screenshots. The 768px (tablet) render is fully faithful —
    768 is `≥sm, <lg`, so both paddings and width match a real tablet. At 390px
    the vertical tap-target heights are exact (`py-3` has no `sm` vertical
    override); only horizontal paddings read the `sm:` variant (marginally
    roomier than a true <640 viewport — a neutral-to-pessimistic direction for
    clipping).
  - Narrow mobile (390px) and tablet (768px), both below `lg`:
    - Collapsed accordion trigger rows measure exactly **44px** tall at both
      widths — meets the WCAG 2.5.5 / iOS-HIG comfortable touch-target minimum.
    - **Zero horizontal overflow** on every result row and inside the grouped
      card body at both widths; no clipping or overlap of child rows.
    - Grouped card is understandable collapsed (one-liner + "Contains N
      children" tag) and expanded (parent-provision block, "Matching children"
      sub-accordion, per-child in-force band/provenance).
    - Top-scoring child is identifiable: `3.2.4.5.` carries the **Top match**
      chip and is the default-open child.
    - Responsive stacking confirmed: at 390px the child titles truncate to one
      line and the parent id/title stack vertically; at 768px titles show in
      full and align side-by-side.
  - Context-child distinguishability verified by server-side render of the
    "smoke" @ 2010-06-01 case (parent `9.10.19.`): the non-match child
    `9.10.19.5.` renders via the `{% else %}` branch as a dashed-border,
    label-only row with a "Context" tag — no caret, no score/Top-match chip, no
    expandable body — clearly distinct from the solid-bordered, left-accented,
    expandable matched children. Row structure is a superset-free simplification
    of the matched row already measured for overflow, so no clipping risk.
